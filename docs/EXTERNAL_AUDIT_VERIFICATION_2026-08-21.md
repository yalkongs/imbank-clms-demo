## 종합 판단과 우선순위 권고

P1~P8이 "규제 제도를 다루는 **화면**"을 만들었다면, 이번 감사는 그 화면들이 딛고 선 **계산 코어의 정합성**을 지목한다. codex의 결론("현재 상태로는 IRB 자본·ECL 부족액·건전성 분류·산업 익스포저를 실제 판단값으로 쓰면 안 된다")은 검증 결과 타당하다. 권고 순서:

- **Track A — 산식 코어 정합성 (차단급, 최우선)**
  - A1. IRB 계산기 통합: 부도/비부도 분기, PD·LGD 입력 하한, 만기 파라미터 단일 소스 (#1·#12, 규모 M)
  - A2. 건전성 분류에서 PD 단독 LOSS 확정 제거 — PD는 검토 트리거로 강등 (#3, 규모 S~M)
  - A3. SICR 최초 인식 스냅샷: 승인 시점 등급·PD 불변 저장 (#4, 규모 M — 기존 decision_snapshot 인프라 재사용 가능)
- **Track B — 데이터 정합성 (수치 신뢰 회복)**
  - B1. 최신 등급 1건 조인으로 교정 (#5, 규모 S — `ROW_NUMBER()=1` 패턴은 covenant.py 등에 기존재)
  - B2. 충당금 원장 단일화: facility 단위 정본 + 가공값 분리 표시 (#6, 규모 M)
  - B3. 순회수가능가액(선순위 공제) 적용 (#7, 규모 S)
- **Track C — 일관성·현실성**
  - C1. 가격 서비스 단일화 (기준금리·FTP 곡선·담보효과 1회 반영) (#8, 규모 M)
  - C2. 상환 스케줄 구조화 + DSCR 재계산 (#9, 규모 M)
  - C3. 결측 대체 provenance 플래그 (#10, 규모 S), 모형 변수 정의 정렬 (#11, 규모 M)
- **보류 판단**: #2(ECL 현금부족액 엔진)는 규제 관점 지적은 정당하나 EIR·계약 현금흐름 스키마 신설이 필요한 대공사(L)로, PoC 단계에서는 Stage2 조건부 PD 구조가 방향은 맞으므로 Track A~B 뒤로 미룬다.

## agy CLI 재시도 방법

agy는 비대화(`--print`) 모드에서 자체 도구 호출 권한을 승인할 수 없어 3가지 방식(`--sandbox`, `--mode plan`, `--disable-slash-commands`) 모두 첫 명령에서 중단됐다. 자동 승인 플래그는 본 세션 권한 정책이 차단했다. 재시도하려면:

1. 사용자가 터미널에서 직접: `! agy -i "$(cat <프롬프트 파일>)"` (대화 모드로 권한 승인 가능), 또는
2. Claude Code 설정에 agy 실행 허용 규칙을 추가한 뒤 재위임.

프롬프트 파일은 세션 스크래치패드 `research-prompt.md`에 있으며 본 문서의 감사 기준과 동일하다.
